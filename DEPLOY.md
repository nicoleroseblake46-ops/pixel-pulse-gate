# One-command deploy — Kali Linux + Nginx + Tor

Production deployment for this Vite + React + Supabase app.
Everything is automated by a single script.

## TL;DR

```bash
cp .env.example .env        # (only if .env doesn't already exist)
sudo ./deploy.sh
```

After the script finishes, the site is live at:

- `http://localhost`
- `http://<your-LAN-IP>` (e.g. `http://192.168.1.42`)
- `http://<auto-generated>.onion` — printed at the end of the script

Re-running `sudo ./deploy.sh` rebuilds and re-publishes safely.

## What the script does

| Step | Action |
| ---- | ------ |
| 1 | Loads `.env` (creates it from `.env.example` if missing) |
| 2 | Installs missing system packages: `nginx`, `tor`, `curl`, `lsof` |
| 3 | Installs Node.js 20 LTS via NodeSource if missing or too old |
| 4 | Frees ports `80` and `8080` if anything is squatting them |
| 5 | Runs `npm ci` (falls back to clean `npm install` on failure) |
| 6 | Runs `npm run build` (retries once after clearing vite cache) |
| 7 | Copies `dist/` to `/var/www/nexuscc` (no `rsync` needed) |
| 8 | Writes `/etc/nginx/sites-available/nexuscc`, enables + reloads nginx |
| 9 | Writes `/etc/tor/torrc.d/nexuscc.conf`, restarts tor |
| 10 | Waits for the `.onion` hostname and prints all three URLs |

## Project structure (deployment-relevant files)

```
.
├── deploy.sh          ← single entry point (run with sudo)
├── DEPLOY.md          ← this file
├── .env               ← VITE_SUPABASE_URL / _PUBLISHABLE_KEY / _PROJECT_ID
├── .env.example       ← template
├── package.json
├── vite.config.ts
└── dist/              ← generated by `npm run build` (served by nginx)
```

System paths the script writes to:

```
/var/www/nexuscc/                     ← served by nginx
/etc/nginx/sites-available/nexuscc    ← reverse-proxy + SPA fallback
/etc/nginx/sites-enabled/nexuscc      ← symlink
/etc/tor/torrc.d/nexuscc.conf         ← hidden service drop-in
/var/lib/tor/nexuscc/hostname         ← your .onion address
```

## Environment variables

Only `VITE_*` vars are baked into the client bundle:

```dotenv
VITE_SUPABASE_URL="https://YOUR-REF.supabase.co"
VITE_SUPABASE_PUBLISHABLE_KEY="your-anon-publishable-key"
VITE_SUPABASE_PROJECT_ID="YOUR-REF"
```

These are **publishable** keys — safe to ship in the bundle. Never put
service-role keys here; they belong in Supabase Edge Function secrets.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `Port 80 already in use` | The script auto-kills the listener. If it persists, run `sudo lsof -iTCP:80 -sTCP:LISTEN` to inspect. |
| `npm ci` fails on Kali | Script auto-retries with a clean `npm install` after removing `node_modules` and `package-lock.json`. |
| Build fails | Script retries once after clearing `node_modules/.vite` and `dist/`. Check `/tmp/nexuscc-build.log`. |
| `.onion` not printed | `sudo cat /var/lib/tor/nexuscc/hostname` once tor finishes bootstrapping (`journalctl -u tor -e`). |
| 404 on page refresh | nginx config includes SPA fallback; re-run `sudo ./deploy.sh` to restore it. |
| Supabase requests fail | `.env` was empty during build — fill it in and re-run the script. |
